# 项目概览

## Project Purpose

“21世纪内阁”用于把分散在微信公众号和 RSS 中的信息集中到一个安静、可控的本机阅读环境。它不试图替用户判断一切，而是帮助用户完成三个动作：稳定收集、主动筛选、持续阅读。

项目原名为 Personal Information Radar（PIR）。当前产品名称与界面用语统一为“21世纪内阁”。

## Product Philosophy

### 信息源管理

信息源是第一层控制单位。每个来源具有等级、类型、同步开关和默认批红规则。关闭批红不会停止同步；暂停同步也不会删除历史文章。

### 人工控制注意力

来源等级表示整体价值，是否进入“批红定案”表示日常注意力资格。二者相互独立。V1.0 还允许在“奏章呈送”中对单篇文章手工加入或移出批红。

### 完整信息流与注意力队列分离

“奏章呈送”保留全部未读文章，“批红定案”只显示来源规则或单篇选择允许进入的未读文章。非批红来源仍然会同步，也仍可搜索、阅读、收藏和进入“继续阅读”。

### 阅读优先

项目不提供算法推荐瀑布流。文章正文按需在后台调阅，成功后进入站内阅读器；失败时保留原文入口。阅读进度、收藏、划线和笔记都保存在本机。

### 用户拥有最终控制权

自动同步只负责搬运信息，不负责替用户决定重要性。V2 即使引入 AI，也应以辅助摘要、标签和建议为主，不能绕过用户现有的来源规则与单篇决定。

## Core User Flow

```text
微信公众号公开文章
        ↓
we-mp-rss 建立订阅并维护 RSS
        ↓
21世纪内阁定时或手动同步
        ↓
奏章呈送（全部未读）
        ├─ 单篇勾选 / 取消批红
        ↓
批红定案（来源规则 + 单篇覆盖）
        ↓
后台调阅正文 / 跳转原文
        ↓
阅读进度 / 已读 / 收藏 / 划线 / 笔记
        ↓
继续阅读 / 收藏 / 札记
```

## V1.0 Actual Scope

- 从本机采集器选择公众号信息源；也可手工录入 RSS/Atom 地址。
- 来源添加、编辑、删除、启停、等级、类型和 Inbox 开关。
- A/B/C 分级同步间隔，最多两个 Feed 并行处理。
- URL 或“来源 + 标题”去重，单个 Feed 失败不阻断其他 Feed。
- 奏章呈送、批红定案、继续阅读、收藏、札记、类型与等级视图。
- 关键词、已读、收藏、等级筛选。
- 微信正文按需调阅、缓存、图片代理、失败回退原文。
- 阅读位置、自动已读、划线、笔记和札记归档。
- 浅色、深色、系统主题与阅读字号设置。
- SQLite 本机存储、每日备份、手动导出和 90 天保留策略。
- 明代内阁主题启动页和中文化产品文案。

V1.0 不包含多用户、云同步、高级全文搜索、独立 Source 详情页、可编辑文章标签、规则引擎或 AI。
