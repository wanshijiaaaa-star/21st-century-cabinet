# V1.0 Status

## Completed

### 信息源与采集

- 手工添加 RSS/Atom 来源。
- 从本机公众号采集器读取并选择未接入公众号。
- 编辑名称、说明、等级、类型、Inbox 和同步开关。
- 删除来源及其文章索引。
- A/B/C 分级同步间隔：12 小时、24 小时、72 小时。
- 最多两个来源并行同步；单源失败不阻断其他来源。
- URL 或“来源 + 标题”去重，重复同步不会重复创建文章。
- 采集器低频维护及更新回调主站。
- 真实发布时间修复和标题重复摘要修复。

### 信息流与批阅

- 奏章呈送：全部未读，按日期及来源等级排序。
- 批红定案：来源规则与单篇人工选择共同决定。
- 单篇红勾支持加入和再次点击取消。
- 批红一键调阅、全部标为已读。
- 奏章呈送全部已读。
- 类型、等级、未读、收藏和关键词筛选。

### 阅读与知识留存

- 微信正文后台按需调阅与本机缓存。
- 失败文章跳转微信原文。
- 图片代理、预留空间和淡入，降低版面跳动。
- 阅读进度、位置恢复、约 95% 自动已读。
- 继续阅读与收藏。
- 正文右键划线、笔记、悬浮提示、编辑和删除。
- 独立札记页及收藏文章的札记摘要。

### 本机体验

- 米白色明代内阁主题界面与卷轴启动页。
- 浅色、深色、系统主题。
- 侧栏收起、响应式布局、`Ctrl/Cmd + K` 搜索快捷键。
- SQLite 本机数据、每日备份、手动导出和 90 天保留策略。
- 一键启动主站和采集器的 Windows 脚本。

## Partially Completed

- Source 页面有卡片、快速开关和编辑弹窗，但没有单独的 Source 详情页或单 Source Sync。
- Article tags 可显示并参与数据保存，但没有面向用户的标签编辑界面，也没有 Tag 数据表。
- 筛选支持关键词、已读、收藏、等级、类型和侧栏视图，但没有 Source/Tag/Inbox 状态的任意组合筛选器。
- 同步错误会记录 `lastError`，但来源卡片只显示“同步失败”，未展示详细原因。
- 采集器 Vue 源码包含本机增强，但日常运行使用 `static/` 中已构建资产；修改 Vue 后需显式重新构建并复制。
- 静态界面可以单独预览，但没有本机 Python/SQLite 服务时不具备完整数据能力。

## Known Limitations

- 单用户、本机、Windows 优先；没有账号隔离、云端同步或移动端原生应用。
- 微信公众号正文和发布时间能否取得取决于微信页面、授权与反爬状态。
- Feed 仅解析每个来源最近 30 个 item。
- 没有高级全文索引，搜索只匹配标题、摘要和来源名称。
- 主站 Source/Article 以单个 JSON 状态保存，适合个人规模，不适合多用户或超大数据量。
- 没有正式的主站自动化测试套件；目前依靠语法检查、API 冒烟和浏览器验收。
- 启动采集器脚本使用本机固定虚拟环境路径 `%LOCALAPPDATA%\CenturyCabinet\we-rss-venv`。

## Known Issues

### High

- `we-mp-rss/web_ui` 的生产依赖在 2026-10-03 执行 `npm audit --omit=dev` 时报告 9 项告警（6 High、3 Moderate），涉及 Axios 及若干间接依赖。当前用途是仅监听本机的单用户工具，实际暴露面有限，但在完成依赖升级和回归测试前，不应把采集器端口暴露到公网或不可信局域网。

### Medium

- `article_content` 和 `annotations` 没有外键。来源被删除或文章因保留策略淘汰时，可能留下孤立正文缓存；数据库规模较小时影响有限。
- Continue 只依据 `0 < progress < 0.95`，因此手工标为已读但进度不足 95% 的文章仍会出现。
- 主站 `package.json`、Vinext/Drizzle 配置是早期脚手架遗留，不能作为本机运行方式；真实命令已经在 README 中单独说明。
- 采集器前端生产包存在大于 500 kB 的分块、第三方国际化代码使用直接 `eval` 等构建警告；不影响本机启动，但会增加加载、审计和未来公网部署成本。

### Low

- 采集器当前仍有一篇正文状态为 `failed` 的文章；UI 会按设计回退原文。
- 无法从微信页面取得时间时会显示“时间未知”，不会用本机同步时间伪装发布时间。
- 部分上游采集器控制台日志仍以系统代码页显示乱码，不影响数据与接口。
- 上游 `apis/cascade.py` 留有“结果上报” TODO；本机单节点采集链路不使用级联结果上报。

当前没有已知 Critical 问题。依赖告警不阻塞本机 V1.0 基线交付，但阻塞公网部署判定。

## Important Implementation Notes

1. 修改文章卡片时同时检查 `dist/index.html` 和 `dist/reader-features.js`；后者会覆盖前者的 `articleCard`。
2. `manualInbox` 是三态覆盖，不要用简单 truthy 判断替代当前逻辑。
3. “一键调阅”必须使用 `articleInInbox()`，不能只检查 `source.inbox`。
4. “奏章呈送”当前定义为全部未读，不是自然日 Today。这是用户确认后的产品语义。
5. 发布时间未知时必须保留未知，不能回退到同步时间或当前时间。
6. 正文首次点击只应后台调阅，不能在完成或失败时自动弹出 Reader 打断当前阅读。
7. 公开发行版以根目录作为单一 Git 仓库，`site` 与 `we-mp-rss` 必须保持同级。
8. `we-mp-rss/data`、`site/data`、Cookie、密码和本机私有配置均不得提交。

## Plan vs Actual Differences

- 计划：Next.js + Prisma +规范化 Source/Article/Tag 表。实际：静态前端 + Python + SQLite JSON 状态。
- 计划：Today 为当天全部文章。实际：“奏章呈送”为全部未读。
- 计划：Article 不保存 Inbox 状态。实际：为满足单篇批红，加入 `manualInbox` 三态覆盖。
- 计划：正式划线依赖外部浏览器插件。实际：V1 已实现站内划线、笔记和札记。
- 计划：不主动抓网页正文。实际：通过本机采集器按需调阅微信正文。
- 计划：Source Tag。实际：来源标签已取消；仅保留文章 tags 数据，但没有编辑器。
