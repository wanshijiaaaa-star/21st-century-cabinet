# V1.0 发布审计

审计日期：2026-10-03  
审计对象：`site` 主站与同级 `we-mp-rss` 公众号采集器  
结论：可作为单用户、本机优先的 V1.0 稳定基线交付；不具备公网部署条件。

## 审计范围

- 以实际代码、数据库和运行接口为准复核产品能力，不以早期计划书作为已实现事实。
- 检查信息源、同步、奏章呈送、批红定案、阅读器、阅读进度、收藏、札记和搜索链路。
- 检查两个 Git 仓库的改动、残留 TODO、数据库完整性、语法、测试、构建和依赖公告。
- 仅做与 V1.0 稳定交付直接相关的修复，不重构技术栈，不提交、不打标签、不推送。

## 数据与隐私验证

审计使用本机测试数据验证数据库完整性、正文状态、批注和采集器链路。公开发行版不包含测试者的信息源、文章、批注、用户、Cookie 或授权快照。

运行数据固定保存在 `site/data` 与 `we-mp-rss/data`。两个目录均被 Git 忽略，并由发布前隐私检查脚本阻止误提交。

## 本轮稳定性修复

- 统一批红三态规则：来源默认、单篇强制加入、单篇强制排除。
- 让“一键调阅”和 WebMCP 的批红列表都使用同一 `articleInInbox()` 规则，避免漏掉手工红勾文章。
- 修复采集器订阅表单的错误重置字段、弱类型种子文章和遗留调试输出。
- 保留真实发布时间，无法取得时显示“时间未知”，不以同步时间伪装。
- 修复标题被用作摘要；摘要限制为两行视觉长度并以句号结尾。
- 补齐实际架构、数据库、状态、迁移、使用和版本文档。

## 未解决事项

### 发布前不阻塞本机使用

- 一篇正文调阅失败，需要从原文阅读。
- Continue 视图只按进度判断，可能包含已手工标为已读但进度不足 95% 的文章。
- 正文和批注表没有外键，长期运行后可能出现少量孤立缓存。
- 主站尚无正式自动化测试套件；当前以语法检查、API 冒烟和浏览器验收覆盖。

### 阻塞公网部署

- 采集器生产依赖的 9 项 npm 安全告警尚未完成升级回归。
- 采集器前端存在大分块和第三方直接 `eval` 构建警告。
- 系统是单用户本机设计，没有公网威胁模型、账号隔离、TLS、集中密钥管理或正式部署方案。

## Git 与版本建议

公开发行版使用全新的根仓库，避免把历史中的私人订阅清单带入 GitHub。`site` 与 `we-mp-rss` 在该仓库中作为两个普通同级目录管理。

正式发布前应运行 `scripts/privacy-check.ps1`，完成功能验收后创建 `v1.0.0` 注释标签和对应 GitHub Release。采集器的上游来源与 MIT License 保留在根目录的第三方声明中。

## V2 就绪判断

V1 已具备可迁移的核心资产：稳定的用户语义、来源与文章状态、真实正文缓存、阅读进度、收藏和批注数据。V2 可以在不改变“奏章呈送/批红定案”语义的前提下，先把 JSON 状态规范化，再增加全文搜索、清理任务和可选 AI 能力。具体边界见 `v2-migration-notes.md`。
